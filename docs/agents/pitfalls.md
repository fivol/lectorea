# Mistakes already made

[← agents](README.md)

Every entry is a real case rather than a hypothetical. One shape throughout:
**what was assumed**, **what it turned out to be**, **how not to repeat it**. The
last line matters most — it has to work for a class, not for one file.

---

## Data and formats

### The shape of a JSON file was assumed rather than checked

**Assumed:** `public/data/courses.json` is an array of courses, so `built.map(…)`
will work.
**It was:** an object, `{ maxLevel, columns, courses }`. The script failed on the
first line that touched it, after everything else had been written.

**How not to repeat it:** before the first access to an unfamiliar JSON file,
three lines of `tsx -e` printing `Array.isArray`, the top-level keys and the keys
of the first element. Cheaper than reading the code that writes it, and more
reliable: the file is generated by a script that may have changed.

### A channel id exists in two forms

**Assumed:** the set "channels in `channels.yaml`" and the set "channels from the
API" can be compared directly.
**It was:** the file is written in handles (`@yalecourses`) because a handle is
readable; the API answers `UC…`. The list of "channels not in the file"
triumphantly produced YaleCourses and Лекториум, which the catalogue has been
crawling for months.

**How not to repeat it:** resolve through the `channels` table in `cache.db`,
where `discover` wrote both forms once. The wider rule: **an entity here can have
two names, and the hand-edited file almost always carries the readable one while
the API answers with the canonical one.**

## Quota and accounting

### Spend was counted by hand, and the error paths do not agree

**Assumed:** "the call threw, so no units were spent" — the spend can be tallied
in the loop.
**It was:** the error paths differ. `TransientError` (a rate limit) arrives
**after** the request — the units are gone. `QuotaExceededError` is thrown
**before** any request, when no key has room — nothing was spent. A budget that
guesses which is which is wrong in the direction that overruns it.

**How not to repeat it:** read the spend from the ledger — `api.spent()` before
and after — rather than reconstructing it from what came back. The ledger knows
the fact; the caller only knows the intent.

### An expensive call with no retry

**Assumed:** a transient failure behaves as it does everywhere else in the
pipeline — the queue will ask again later.
**It was:** `search.list` has already been charged when the 403 arrives. Giving
up throws away 100 units and gets nothing; retrying spends 100 more and gets the
answer.

**How not to repeat it:** the price of a call decides its retry policy. For
1-unit endpoints the queue is enough; for a 100-unit one, a retry on a rate limit
is not optional.

## Rules and matching

### A rule reads the title and cannot see past it

**Assumed:** if the rules bound a playlist to a course confidently, it is
material.
**It was:** «Linguistics», 50 videos, by a channel called *A random human* —
somebody's bookmarks, collected from forty other channels. The title names the
subject, the size is right, confidence 0.95. Queueing the batch would have paid
to walk 910 such collections.

**How not to repeat it:** **a title filter cannot see what is not in the title.**
When the decision costs quota, ask the source rather than the text:
`playlistItems.list` returns the owner of every video for one unit and separates
a course from a collection and from a mirror. Generally — before paying for
material, find out whose it is.

### A tolerance written for one language was assumed to be neutral

**Assumed:** `findPhrase` allows three letters on a phrase's right edge, so the
singular of any plural keyword is strictly better — it matches both forms.
**It was:** the tolerance exists for Russian inflection and has no idea which
language it is in. On multi-word phrases the singular really is strictly
better; on one-word English keywords those three letters are a different word.
`graph` reaches «Graphics», `gene` reaches «General», `rock` reaches «Rocket».
The measurement that looked like a 208-playlist win for `graphs` → `graph` was
208 wrong bindings.

**How not to repeat it:** when a rule carries a comment naming the language or
the case it was written for, that comment is a scope, not a description. Before
generalising it, list what it would do to the *other* case and read the titles —
[data-traps.md](data-traps.md#english-plurals-store-the-singular-and-only-when-the-phrase-has-two-words)
has the table this produced.

### A gain was counted without checking the gain was not already there

**Assumed:** counting titles where a keyword's singular matches and its plural
does not measures what adding the singular would buy.
**It was:** it measures nothing of the sort unless the singular is absent from
the index and the playlist is currently unbound. `operating system` was already
a keyword and the script proudly reported 26 new bindings for adding it again;
the population it counted was every live playlist, most of them already bound.

**How not to repeat it:** a hand-rolled estimate of a rule change answers a
question of its own devising. `_probe.ts` exists, it runs the real pass over the
real corpus and diffs against the stored verdict — **take a baseline, make the
edit, probe again, subtract.** The baseline is not optional: a crawl running in
another window moved it by 50 bindings while this was being measured.

### Vetting a channel by its numbers passes things that are not courses

**Assumed:** `_vet.ts` printed «✓ 85 playlists of 10+», so the channel qualifies.
**It was:** a conference archive (*TALE*, 438 playlists: «CAAUK 2018»,
«TAG@25 2003»), or chapters instead of courses («General Chemistry 1 Chapter 7»,
«Chapter 8»), or somebody else's commercial course re-uploaded whole.

**How not to repeat it:** the `✓` means "there is something to look at", not
"this qualifies". **Always read the playlist titles**; the bar is in
[harvest.md](../harvest.md#the-bar). Numbers shortlist candidates; the decision
belongs to whoever read the titles.

## Reports and repeat runs

### A run's counter was printed as a state of the world

**Assumed:** a report can print whatever this run's passes counted.
**It was:** on a resume (`--from`) the passes did not execute, and the report
cheerfully announced "0 collections" where there were 309. The number described
a state that does not exist.

**How not to repeat it:** derive the figures from the data
(`candidates.filter(…)`), not from this run's tallies. Print a run counter only
next to the run that produced it.

### A comment promised a property the code did not have

**Assumed:** having written in the docstring that `--from` gives past spending
the benefit of new rules, the matter was settled.
**It was:** `--from` loaded the stored verdicts and re-judged nothing.

**How not to repeat it:** when a comment claims a property, check the code has it
in the same sitting. A comment that lies is worse than a missing one — it is read
as verified.

## Environment

### The quota ledger is keyed by the Pacific day

**Assumed:** "today" in the `quota` table can be had from SQL `date()`.
**It was:** `quotaDateKey()` formats the date in `America/Los_Angeles`, because
the quota resets at Pacific midnight. `date()` gives the UTC day and is wrong for
part of every day; the local date is wrong more often.

**How not to repeat it:** ask `lib/db.ts` for the key rather than recomputing a
date. Anywhere a value is derived by a rule with a comment above it, the rule is
the interface — see [workflow.md](workflow.md#quota-is-the-scarce-resource).

### The git index is shared with other sessions

**Assumed:** `git add -A` before committing is fine.
**It was:** other sessions work in this same working tree, and their files land
in my commit (and mine in theirs).

**How not to repeat it:** **always `git add` an explicit list** of the files you
changed, and check `git status --short` before committing. The `git status` from
the start of a session is a snapshot, not live state: files that were there may
belong to somebody else's commit by the time you reach yours.

### …and so is `public/data`, which no `git add` discipline protects

**Assumed:** the sharing problem is about *committing*, so naming files at
`git add` covers it.
**It was:** `pnpm data:build` runs whatever `scripts/08-build.ts` says right
now, and another session had it half-way through an LLM-verdict gate that keeps
out any playlist with no verdict row yet. The build succeeded, said
`✓ built in 36396 ms`, and wrote a catalogue of 1356 playlists over the 6825 that
were there. `public/data/` is in `.gitignore`, so there was nothing to check
out: it had to be built again.

**How not to repeat it:** before running anything that *writes* — `data:build`,
the `make` sequences, a script that touches `cache.db` — check
`git status --short` for edits to the scripts it will run, not only for the
files you are about to commit. Uncommitted work in `scripts/` is somebody's
half-finished idea, and running it publishes that idea over the shared state.

The way out, when it is needed, keeps the shared tree untouched:

```bash
git worktree add --detach "$SCRATCH/build-head" HEAD
```

then symlink `data/cache.db` (and `-shm`, `-wal` — it is 18 GB, never copy it)
and `node_modules` into the worktree, copy across any `data/` files you have
edited yourself, build there, and copy `public/data` back. `git stash` on their
files would have been the faster fix and the wrong one: it edits the tree they
are working in.
