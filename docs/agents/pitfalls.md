# Ошибки, которые уже совершены

[← agents](README.md)

Каждая запись — реальный случай, а не гипотеза. Формат один: **что предположил**,
**чем это оказалось**, **как не повторить**. Формулировка «как не повторить» важнее
самой ошибки: она должна работать для целого класса, а не для одного файла.

---

## Данные и форматы

### Форма JSON предполагалась, а не проверялась

**Предположил:** `public/data/courses.json` — массив курсов, `built.map(...)` сработает.
**Оказалось:** объект `{ maxLevel, columns, courses }`. Скрипт упал на первой же строке
после того, как всё остальное было написано.
**Как не повторить:** перед первым обращением к незнакомому JSON — три строки
`tsx -e`, печатающие `Array.isArray`, ключи верхнего уровня и ключи первого элемента.
Это дешевле любого разбора кода, который его пишет, и надёжнее: файл собирается
скриптом, который мог измениться.

### Идентификатор канала существует в двух формах

**Предположил:** множества «каналы из `channels.yaml`» и «каналы из API» сравнимы напрямую.
**Оказалось:** файл написан хэндлами (`@yalecourses`), потому что хэндл читаем; API отвечает
`UC…`. Список «каналов, которых нет в файле» гордо предъявил YaleCourses и Лекториум —
их каталог краулит месяцами.
**Как не повторить:** сравнивая каналы, резолвить через таблицу `channels` в `cache.db`,
где `discover` однажды записал обе формы. То же правило шире: **в этом проекте у сущности
может быть два имени, и файл почти всегда написан читаемым, а API отвечает каноническим.**

## Квота и учёт

### Расход считался вручную, и пути ошибок не согласованы

**Предположил:** «вызов упал → единицы не потрачены», можно считать спенд в цикле.
**Оказалось:** пути ошибок ведут себя по-разному. `TransientError` (rate limit) приходит
**после** запроса — единицы списаны. `QuotaExceededError` бросается **до** запроса, когда
ни у одного ключа нет места — не списано ничего. Бюджет, который угадывает, ошибается
в сторону перерасхода.
**Как не повторить:** расход читать из реестра — `api.spent()` до и после, — а не
реконструировать по возвратам. Реестр знает факт; вызывающий знает только намерение.

### Дорогой вызов без повтора

**Предположил:** транзиентная ошибка — как везде в пайплайне, очередь переспросит позже.
**Оказалось:** у `search.list` единицы списаны **до** того, как пришёл 403. Отказ от
повтора выбрасывает 100 единиц и не получает ничего; повтор тратит ещё 100 и получает ответ.
**Как не повторить:** цена вызова решает политику повтора. Для 1-единичных эндпоинтов
достаточно очереди; для 100-единичного повтор на rate limit обязателен.

## Правила и матчинг

### Правило читает название и не может видеть большего

**Предположил:** если правила уверенно привязали плейлист к курсу — это материал.
**Оказалось:** «Linguistics», 50 видео, канал «A random human» — чужие закладки,
собранные с сорока каналов. Название называет предмет, размер правильный, уверенность 0.95.
Массовая постановка в очередь оплатила бы обход 910 таких подборок.
**Как не повторить:** **фильтр по названию не видит того, чего нет в названии.**
Когда решение стоит квоты, спрашивать источник, а не текст: `playlistItems.list` за одну
единицу отдаёт владельца каждого видео и отличает курс от подборки и от зеркала.
Обобщённо — прежде чем платить за материал, проверить, чей он.

### Проверка канала по числам пропускает не-курсы

**Предположил:** `_vet.ts` показал «✓ 85 плейлистов из 10+» — канал подходит.
**Оказалось:** это архив конференций (*TALE*, 438 плейлистов: «CAAUK 2018», «TAG@25 2003»),
или главы вместо курсов («General Chemistry 1 Chapter 7», «Chapter 8»), или перезалив
чужого коммерческого курса.
**Как не повторить:** галочка `_vet.ts` — это «есть что смотреть», а не «подходит».
**Всегда читать названия плейлистов глазами**, планка — в [harvest.md](../harvest.md#the-bar). Числа
отбирают кандидатов; решение принимает человек или агент, прочитавший названия.

## Отчёты и повторные прогоны

### Счётчик прогона выдан за состояние мира

**Предположил:** в отчёте можно печатать то, что насчитали проходы этого запуска.
**Оказалось:** на возобновлении (`--from`) проходы не выполнялись, и отчёт бодро сообщил
«0 подборок» там, где их 309. Число описывало состояние, которого нет.
**Как не повторить:** итоговые цифры выводить из данных (`candidates.filter(...)`),
а не из счётчиков конкретного прогона. Счётчик прогона печатать только рядом с прогоном.

### Комментарий обещал свойство, которого в коде не было

**Предположил:** написал в докстринге, что `--from` даёт прошлым тратам выгоду от новых
правил, — и на этом успокоился.
**Оказалось:** `--from` загружал сохранённые вердикты и ничего не пересуживал.
**Как не повторить:** если комментарий заявляет свойство — проверить, что код им обладает,
в тот же заход. Комментарий, который врёт, хуже отсутствующего: его читают как проверенное.

## Репозиторий

### Индекс git общий с другими сессиями

**Предположил:** `git add -A` перед коммитом — нормально.
**Оказалось:** в этом рабочем каталоге параллельно работают другие сессии, и их файлы
попадут в мой коммит (а мои — в их).
**Как не повторить:** **всегда `git add` явным списком файлов**, которые изменил сам,
и сверять `git status --short` до коммита. `git status` в начале сессии — снимок, а не
живое состояние: файлы, которые там были, к моменту коммита могут быть уже чужими.
