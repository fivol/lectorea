What the site is and who it is for: [the main README](../README.md). This page
is the technical entry point — every other document is linked from here.

A static catalogue: there is no backend. All content is JSON generated by a
pipeline of scripts and served as files; the user profile lives in
`localStorage`. The live site is [lectorea.org](https://lectorea.org/),
deployed from `main` by [deploy.yml](../.github/workflows/deploy.yml).

It also keeps itself current without anybody pressing anything: a nightly job
re-crawls what is already known, drops what has died, and the deploy runs off
the back of it ([pipeline.md](pipeline.md#automation)).

## Quick start

```bash
pnpm install
```

```bash
pnpm data:build
```

```bash
pnpm dev
```

That is `data/` (+ `cache.db` if present) → `public/data`, then the frontend on
`localhost:5173`.

Without `cache.db` the build produces the graph with no playlists — enough to
work on the interface. To get a catalogue with material in it without spending a
day of YouTube quota, seed synthetic data:

```bash
pnpm data:seed-dev && pnpm data:build
```

They are marked `[dev]` and obviously fake; remove them again with:

```bash
pnpm data:seed-dev --wipe
```

Crawling YouTube needs an API key — [setup.md](setup.md).

## The graph

A **course** is an abstract unit of knowledge ("Probability theory"); a
**playlist** is one concrete realisation — MIT 6.041, HSE lectures, a tutor's
channel. One course, many playlists.

Dependencies hang on the course, never on the playlist: otherwise the graph
would be rebuilt for every university, and the catalogue would grow fifteen
duplicates of probability theory. Only **direct** dependencies are stored — if
A → B → C, then C records only B — and the transitive closure is computed.

`level`, the column, is the longest `deps` chain ending at a node. It is never
assigned by hand, which makes a course placed before its own prerequisite
impossible by construction and turns the layout itself into a check on the
markup. The price is that depth depends on how courses are sliced: split
calculus into four parts and all of physics shifts a column to the right. Hence
the rule in [CONTRIBUTING.md](../CONTRIBUTING.md): **one unit = one semester
course.**

![The columns, with a course selected](images/courses.webp)

`pnpm data:build` is also the validator — schemas, cycles (it prints the loop),
dangling dependencies, misfiled courses — and it warns about markup that builds
but rots the graph. The full list is under
[what CI checks](../CONTRIBUTING.md#what-ci-checks).

## How it is put together

Vite, React 18 and TypeScript, Tailwind, deployed as static files to any host.
Scripts are `tsx` + better-sqlite3; tests are vitest over the build logic.

| Decision | Why |
|---|---|
| React Router | the URL carries the view: sharing, back button |
| Zustand | context would re-render every card on every hover |
| zod schemas in `shared/schema.ts` | one schema for the scripts, the build and the frontend |
| CSS variables behind Tailwind | one palette the map screen can swap wholesale at runtime |
| One UI kit in `src/components/ui/` | every button, chip, field and switch cut from the same plate, in one file |
| Own barycentric column ordering, at build time | dagre cannot express domain bands, and ranks nodes by edge length rather than by level |
| Plain scrollable columns; arrows only for the selected chain | over 200 cards, arrows were noise |

## Everyday commands

```bash
pnpm dev
```

```bash
pnpm build
```

```bash
pnpm test
```

```bash
pnpm typecheck
```

`build` produces `dist/`; `test` covers the build logic — levels, cycles, column
order, score, search. The catalogue-side commands (`data:build`, `course:new`,
`playlist:add`, `check:i18n`, `stats`) are in
[scripts/catalogue.md](scripts/catalogue.md), and everything else — the crawl,
the matching, the map generators — is under [scripts/](scripts/README.md).

Three jobs are a sequence rather than a command, and getting the order wrong
costs a day of quota or publishes half a state. Those have a `Makefile` —
`make` on its own prints the list:

```bash
make pipeline
```

```bash
make publish
```

```bash
make stats
```

The whole crawl in quota order; the local state of the system published whole,
guarded against the half of it that is easy to leave behind; and the dashboard.
What each one does and why in that order:
[scripts/README.md](scripts/README.md#the-three-sequences-with-a-shorter-name).

## Contributing

All content is open and changes go through pull requests. Every course panel has
a «Исправить данные» link straight to the file, and every empty course a
«Предложить плейлист» button that opens a pre-filled issue — both pointing at
whichever repository the site was built from, so a fork sends its readers to its
own issues without a line being edited ([setup.md](setup.md)).

An issue is the whole of what a reader has to do: the four forms in
[.github/ISSUE_TEMPLATE](../.github/ISSUE_TEMPLATE) ask for five required fields
between them, and a playlist takes one — the link, since the rest comes from the
YouTube API. Maintainers work through them in batches with `/issues`
([.claude/commands/issues.md](../.claude/commands/issues.md)), which checks each
one against the API and the repository before anything is written.

Two rules carry the rest: one unit is one semester course, and dependencies are
taken from syllabi rather than invented. Both are in
[CONTRIBUTING.md](../CONTRIBUTING.md).
